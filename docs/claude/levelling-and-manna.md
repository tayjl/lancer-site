# Levelling and manna

Covers: Homebrew levelling, manna, licences, core bonuses, experience and the reward log.
See also: [biomods.md](biomods.md), [pilot-inventory.md](pilot-inventory.md), [stats.md](stats.md), [gm-pages.md](gm-pages.md).

- **Homebrew levelling and gear** (decided by the developer, 2026-10-29; `docs/lancer-rules.md`, prices in `PRICES` in `src/rules.ts`):
  - **Level** is gained narratively only: GMs and owners set it. It raises **HASE points (2 + level)** and **biomod capacity, the mod limit (6 + level)**. Nothing else.
  - **Manna buys everything else:** licence ranks **600** each, biomods (bionics) at **their own price** (`bionics.manna_cost`, set in the content editor; existing ones were set to 500 on 2026-11-18 so no balance changed), talent ranks **300** each, owned pilot gear that isn't free (its price, see [pilot-inventory.md](pilot-inventory.md)), and **mechs: the first is free, each one after it 500** (`PRICES.extraMech`; the developer, 2026-11-19; `mannaSpent(sheet, bionicPrices, mechs, gear, live)` takes the mech count from the card's `mechs` list, so scrapping a mech refunds it and pilots who already had several mechs lost 500 per extra one; the hangar's `New mech` shows `New mech · 500` from the second and uses the blocked pattern with "Not enough manna"; GM change review counts an added mech in the cost of change like any purchase). **New pilots start with 2000 manna** (`STARTING_MANNA`, the column default from migration `20261121090000_starting_manna_2000.sql`; existing pilots keep what they have). **GMS gear is free to print**, and licensed gear (frames, weapons, systems) is free once the pilot holds that licence rank.
  - **Licence level** is just the number of licence ranks bought (no separate number).
  - **Alternate frames** (2026-11-18; packs mark one with `variant` = the original's name and usually `license_id` = the original's id, e.g. Worldkiller Genghis, Empakaai): **one licence per original frame.** `alternateOf()` / `licensedFrames()` / `licenceFrames()` / `chosenFrame()` in `mechData.ts`; the licence picker, archives' Licences and manufacturer counts list originals only, and the alternate appears in the original's ladder at its own rank. The pilot picks which frame the licence gives (`sheet.frame_choices`, licence id → frame id, free; radios on the licence card once the rank is held, a "Chosen frame" line when read-only); the frame picker blocks the other (`frameBlockedBy()` in `rules.ts`, "Licence gives X"); `mechProblems()` and `pilotProblems()` flag a mech on the wrong frame and a licence still held under an alternate's id (never auto-rewritten; a GM moves its ranks). Change review shows a changed choice as an Updated line in licences. The frame form has an "Alternate of" select. Tested in `src/alternateFrames.test.ts`.
  - **Core bonuses:** one free pick for every **3 licence ranks** bought. Each non-GMS bonus also requires **3 ranks in its manufacturer**, across any of its licences (6 for a second bonus from that manufacturer, etc.). GMS bonuses have no manufacturer requirement. The picker blocks ineligible choices; the shared rule check flags existing selections that lose eligibility, including in GM reviews. No bonus can be taken twice. Existing selections are never silently removed.
  - **Where it's stored:** `character_sheets.level` and `character_sheets.manna` (manna *received*, in total). Both are GM-only: a trigger refuses changes from anyone else, even a player whose pilot is pending (migration `20261029022434_level_and_manna.sql`, which also dropped the old hand-set `mod_points`). What's **spent** is worked out from the sheet (`mannaSpent()`), so the balance (received minus spent) can't be faked, lowering a rank refunds it, and the pickers block anything the balance can't cover.
  - **GMs set them** in the **gm: pilots** roster (editable level, experience and total manna received) or on any pilot's review page ("GM controls", `Save rewards`). Every record links there for GMs. They save on their own button only: approving or sending back never needs them (the developer's request, 2026-10-29).
  - **Experience and the reward log** (2026-11-19, migration `20261119160000_rewards_and_experience.sql`, tested in `supabase/tests/rewards.test.sql`; on the hosted project): a **GM-only** number per pilot, 0–1000, in `pilot_progress` (`character_id` primary key, `experience`, `updated_at`; no row means 0). At 1000 the pilot is "ready to level", but nothing is automatic: a GM raises the level. Every change to a pilot's **level, manna received or experience** is recorded in `pilot_reward_log` (`character_id`, `field`, `old_value`, `new_value`, `reason`, `changed_by`, `changed_at`), by **triggers** (`private.log_sheet_rewards()` on `character_sheets`, `private.log_experience()` on `pilot_progress`, both `security definer`), so a change made anywhere, the dashboard included, is logged (with no reason, and `changed_by` null when there is no logged-in user). **Both tables are GM-only** (RLS: GMs and owners read; nobody has a write grant; players and visitors get nothing, even for their own pilot), kept apart from `character_sheets` because players can read their own sheet. Writes go through two `security definer` functions that check `is_gm()` themselves: `award(target_character_id, new_level, new_manna, new_experience, reason)` (nulls leave a field unchanged; whole numbers, 0 or more, experience at most 1000; sets the reason as a transaction-local setting `app.reward_reason` that the triggers read, all in one go) and `level_up(target_character_id, reason)` (refused below 1000 experience; level + 1, experience − 1000, reason defaults to "Level up"). The roster and GM controls call them (`src/rewards.ts`: `award()`, `levelUp()`, `rewardsProblem()`, `describeReward()`, tested in `src/rewards.test.ts`); nothing on the site writes level or manna to `character_sheets` any more. Players see nothing new.
- **Licence levels:** the pilot's licence ranks in each frame, bought with manna; licence level is their total (homebrew, see Levelling above).
- **Talents and core bonuses:** included.
- **Manna:** the in-universe currency. It isn't in LANCER's data. GMs record how much each pilot has received (`character_sheets.manna`), and what's spent is worked out from the sheet (homebrew, see Levelling above). Players never change it directly. It stays private to the pilot's player and GMs (the rest of the sheet and level went public 2026-11-19, manna did not).
