# Images

Covers: Pilot and mech pictures: uploads, bundled frame art and the one component that draws them.
See also: [mech-page.md](mech-page.md), [pilot-profile.md](pilot-profile.md), [content-editor-forms.md](content-editor-forms.md).

- **Images (built 2026-11-17):** pilot portraits and mech images, uploaded by whoever can edit the page (the player on their own pending pilot or draft change, GMs in edit mode). Pasted links aren't supported (Discord attachment links expire). The browser shrinks each picture first (`src/images.ts`: long side at most 1024px, WebP at 0.85 quality, JPEG on Safari; inputs over 20 MB refused; animated GIFs become still) and uploads it to the `character-images` Storage bucket as `<uploader's user id>/<random id>.webp` (`.jpg`). The bucket is **public to read** (pending pilots' public cards are visible to every logged-in user anyway), 1 MB, WebP and JPEG only; uploads are immutable (no update policy): users insert into their own folder only and delete from it, GMs and owners delete anywhere (migration `20261117180750_image_uploads.sql`, tested in `supabase/tests/images.test.sql`). **The card stores the path, never a URL** (`characters.pilot_image`, and `image` in each `characters.mechs` entry); `imageUrl(path)` builds the public link with no network and returns null for anything not matching `IMAGE_PATH` (a database check constraint enforces the same shape on `pilot_image`), so a tampered value can't point the page at an outside site.
- **Frame art (2026-11-19):** official frames have artwork bundled from Massif's frame images (the files COMP/CON shows, which lancer-data's `image_url` points to on Massif's CDN, not in the COMP/CON repo; GPL-3.0, credited in the README): `src/assets/frames/<frame id>.webp`, 53 files for the frames in core and the eight expansion packs the site supports (long side at most 640px, quality 82, about 4.2 MB in all; frames whose pack art is a `nodata` placeholder, Sagarmatha and Chomolungma, have none; Everest's is Massif's "NO IMAGE DATA" placeholder, so it isn't bundled either and the GMS frames all show the placeholder symbol). `frameArt(frame, frames)` in `src/images.ts` says which picture a frame shows: an owner's upload (the frame's own `image` field, an `IMAGE_PATH` path in the `character-images` bucket, never a URL, separate from the pack's ignored `image_url`), else the bundled art by frame id, else, for an alternate, its original's (tested in `src/images.test.ts`). Bundled art is `import.meta.glob(..., { query: '?url' })` without `eager`, so each image is its own lazy chunk and downloads only when shown; `MechImage.vue` resolves it (`frameArtUrl()`) and draws the `<img>`. `images.ts` imports `auth` only inside `uploadImage()`, so its pure parts load in tests without a browser. Owners upload in the frame form (see [content-editor-forms.md](content-editor-forms.md)). **A mech with no image of its own shows its frame's**, for every viewer now that frames are public, in the hangar card, the mech page's overview (the one place the picture shows on the profile tab). The mech plate has no thumbnail, so nothing to do there. An upload always wins. **`MechImage.vue` is the one component that draws a mech's picture** (2026-11-19): see "Images" at the end of this file.
- **Images:** `src/components/Portrait.vue` is the 3:4 pilot portrait frame (photos and drawings, so it stays boxed). With no image, or when the stored file is gone (the `<img>` errors), it's a calm empty frame (`--raised` fill, thin `--rule` border) with a centred pilot symbol in `--text-dim` and the accessible label "No image". **Mech pictures are `src/components/MechImage.vue`** (2026-11-19; one component for the hangar card (`size="card"`, 8rem), the mech page's overview (`overview`, 16rem, 12rem on phones: the one place the mech's picture shows on the profile tab, a minimal Overview panel holding just the picture for a mech with no frame), licence cards (`licence`, 11rem wide, 10rem tall), the frame picker rows (`pick`, 64px, 48px on phones), the information dialog and archives pane (`info`, 16rem) and the frame editor (`editor`)). It takes the stored upload path (`src`), the frame's picture (`art`, from `frameArt()`) and the maker's logo, and always shows something, in this order: the upload (a plain picture with rounded corners, no box), else the frame art (a transparent cut-out drawn straight on the page surface, standing on the bottom edge, no shadow), else a dim `--text-dim` placeholder in the same space (the maker's logo if known, else the frame symbol, half the height). A picture that fails to load (a deleted upload, a missing file) falls through to the next one, so there is never a broken-image icon. Each size reserves its height, so the page doesn't jump while art loads and cards line up with or without art. `InfoBody` shows it for frames and licences (`Info.art` null = a frame with no art; undefined = not a frame); the frame picker keeps its mini radar when a frame has no art. It takes the stored image path (`src`) and resolves it with `imageUrl()`; the header thumbnail and hangar cards use the same helper. `ImageUpload.vue` goes under the portrait only while the page is `editable` (the Identity panel on the profile tab, the mech page's Image panel): a `.small` `Upload image` / `Replace image` (a hidden file input) and a `.quiet.small` `Remove image` (no confirmation: uploading again undoes it), "Uploading…" / "Saving…" in dim text, and a red "Not saved: …" under them. The path is saved by the page's own `updateCharacter()`, so drafts, GM edit mode, conflicts and Retry all work as for any other field. **Clean-up is best effort and client side** (`useMyPilot`: `savedImages` / `approvedImages`): a file is deleted once a successful save stops using it and the approved card (while a draft is open) doesn't; withdrawing a draft deletes the images only it used; approving a change (`GmChangeView`) deletes the approved images it replaced; an owner deleting a pilot (`GmReview`) deletes the card's and its mechs' images. Failures are ignored (a player can't delete a GM's file). Images from rejected changes stay (a `shortcut:` comment in `myPilot.ts`).
