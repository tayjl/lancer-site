# Content editor forms

Covers: The content editor forms per kind (weapons, systems, mods, talents, frames, manufacturers) and export.
See also: [content-editor.md](content-editor.md), [lcp-import.md](lcp-import.md).

- **The phase 2 forms** (same shapes as `@massif/lancer-data` `lib/*.json`; fields with no input, such as `skirmish`, `no_mods`, `synergies` and a deployable's `activation`, are kept untouched and reachable through the raw box):
  - **Weapons** (`WeaponForm.vue`): Basics (`ItemBasics` plus mount size, `Auxiliary/Main/Heavy/Superheavy`, and weapon type), then **Range and damage** or **Profiles**, Actions, Deployables, Tags, Bonuses when equipped, and Text (rules, on attack, on hit, on critical hit, lore). A weapon has one set of range and damage at the top, or `profiles[]` (`Split into profiles` moves range, damage and the on-* text into profile 1; going back to one profile folds it up again: `splitProfiles()` / `setProfiles()` in `contentEditor.ts`). With profiles each has its own name (unique), range and damage, and optionally its own tags, rules, on-*, and actions; the weapon's own tags, rules and actions are shared and a profile's replace them while it's in use (that's how `selectWeaponProfile` merges), so empty ones are left out of the data. A licence is a frame's (`license_id` is the frame id, `license` its name, `license_level` I to III); no licence is how the data writes GMS gear (`license: "GMS"`, `license_id: ""`, rank 0), and picking a licence also sets the manufacturer to the frame's. Values the data has but the form doesn't offer (a `Ship-class` mount, a `Special` type) are accepted and kept.
  - **Systems** (`SystemForm.vue`): Basics (type: `System, AI, Shield, Deployable, Drone, Tech, Armor, Flight System, Integrated`; a system with no `type` in the data shows as System and gets one only if changed), Text, Actions, Deployables, Tags, Bonuses.
  - **Weapon mods** (`ModForm.vue`): Basics, **Which weapons it fits** (`allowed_types`, `allowed_sizes`, `restricted_types`, `restricted_sizes` as `ToggleChips`; a list left empty allows everything, as `modBlockedBy` reads it), **What it adds** (`added_range`, `added_damage`, `added_tags`; added damage isn't counted in the weapon's numbers (it's conditional), so its hint asks to say when it applies in the rules text), Text, Actions, Tags, Bonuses.
  - **Talents** (`TalentForm.vue`): name, id, summary (`terse`), description, and **exactly three ranks** (I, II, III: a `fixed` `RepeatList`, a notice with `Make it three ranks` if the data has another count). A rank has a name, rules text, actions, bonuses, `Built in` (`integrated`, picked from every weapon and system, even talent-only ones) and `Optional equipment` (`special_equipment`), and a checkbox for `exclusive` (the highest owned rank's built-in equipment is the only one). Granted items become talent-only (`useMechData()`), so they leave the ordinary pickers. Checks: three named ranks, every granted id exists (`Context.known`).
  - **Frames** (`FrameForm.vue`, `CoreSystemFields.vue`; lancer-data's own `frames.json` shape; `y_pos`, `image_url`, `counters`, `other_art` and a core system's `active_synergies` have no input and are kept): folding `FoldPanel` sections, each with a one-line summary while folded. **Identity** (open; name, read-only id, manufacturer, read-only licence id, `mechtype` roles as `ToggleChips`, the licence rank that unlocks it: None, I, II or III, the **image** (the frame's current picture, bundled or uploaded, with `ImageUpload.vue`: an upload goes to the owner's own folder of the `character-images` bucket, which the existing policies allow, and sets the frame's `image` field; `Remove image` brings the bundled art back; a replaced or removed upload stays in the bucket, a `shortcut:` in the form), and the lore as an `html` rich-text editor), **Stats** (open; every `stats` key as a number box, size one of ½, 1, 2, 3 as a select; Sensors and Save target labelled "(not used)", dimmed), **Weapon mounts** (plain rows of a select with what the mount takes (`MOUNT_HINTS`, now in `mechData.ts`) and up, down, remove, not `RepeatList`, as in the mockup), **Traits** (`RepeatList`: name, use limit, rules, actions, bonuses (mech ones only), deployables), **Core system** (name, lore; Passive: name, rules, actions, bonuses (counted in the stats); Core power: name, activation with its chip, lasts for, switch off with, rules, actions, bonuses (not counted: only active while the power is on); built-in equipment through `ItemIdListField` (`useEquipmentOptions()`, shared with the talent form); deployables) and **Licence unlocks** (read-only: ranks I to III, the frame itself at its rank and the weapons, systems and mods naming it, each opening its information). **A frame is its own licence** (`license_id` = its id, which follows the name until the first save; `license_level` 0 for GMS, 2 otherwise), unless it is an alternate: the "Alternate of" select sets `license_id` to the original's id and `variant` to its name (`checkFrame()` refuses an alternate of itself or of another alternate). A new frame starts as GMS with plain numbers and one Main mount (`blankFrame()`). `checkFrame()`: a name and a manufacturer, an `image` that is not an `IMAGE_PATH` path is an error, a licence rank 0 to 3, every non-"unused" stat a number (whole, 0 or more; tech attack may be negative; size ½/1/2/3), at least one known mount, unique non-empty trait names, a core system name, built-in ids that exist, and the shared action, bonus and deployable checks (paths such as `traits.0.actions.1.name` and `core_system.passive_bonuses.0.val`). **A bonus the build maths doesn't count is now never value-checked** (only warned): the data has accuracy bonuses with no `val` (`{"id":"check","accuracy":1}`), and checking them would have blocked saving any such official frame. The preview needs no "Frame card" tab: frames show Full information only.
  - **The Exotic Gear tag** (2026-11-19): every weapon, system, mod, pilot gear, frame and core bonus whose manufacturer is `EXOTIC` carries `tg_exotic`. `withExoticTag()` in `src/contentEditor.ts` adds it; the editor does so as soon as the manufacturer changes (the tag list shows it, can't remove it, and says "Exotic items always carry Exotic Gear.", `lockedTags()` and `TagListField`'s `locked`), and `createItem()` / `saveItem()` in `src/editorStore.ts` add it again at save, so the raw data box can't skip it. Biomods have no tags. Migration `20261119140000_exotic_tag.sql` (pgTAP `supabase/tests/exotic_tag.test.sql`) adds it to existing items in `data` and `edited`; a tagged prototype with a real manufacturer keeps its manufacturer.
  - **Manufacturers** (`ManufacturerForm.vue`): name, id (typed at creation), logo (one of the bundled ones, `LOGO_NAMES` in `archive.ts`, or none), main colour (`dark`, which the site draws; required, plain 6-digit hex) and darker colour (`light`, optional, not drawn yet) as `ColourField`s, motto (`quote`) and description. The preview is the full information, with the manufacturer's colour as its border and its logo.
- **Export as .lcp** (`exportHomebrew()` in `src/editorStore.ts` and `writeLcp()` in `src/lcp.ts`, `fflate`): the Campaign homebrew's **published** items, files named by kind plus a valid `lcp_manifest.json`; `src/lcp.test.ts` round-trips it through `readLcp()`.
- **Effects, Requirements and Equipment folds (2026-11-21):** every form's bonus section is now **Effects** (`Effects when equipped` on weapons, systems and mods; `Passive effects` / `Power effects` on a core system), a `Requirements` fold is last on weapons, systems, mods, pilot gear, core bonuses, talents, frames and biomods, and core bonuses, systems and biomods have an `Equipment` fold (frame traits and core systems the same fields inline). A biomod keeps its `Stat bonuses` (personal stats, `bonuses`) and gains `Effects` (`effect_bonuses`, no personal stats). Checks for these are in `contentEditor.ts` (`checkRequires`, `checkGrants`, `effectValueProblem`); the editor passes the talent and core bonus ids in `Context`.
- **Not built yet:** forms for frames, weapons, systems, mods, talents and manufacturers (phases 2 and 3); "used by N" on each list row; reordering tags, bonuses or damage.
