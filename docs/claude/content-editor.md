# Content editor

Covers: The owner content editor: how it works, saving, shared fields.
See also: [content-editor-forms.md](content-editor-forms.md), [lcp-import.md](lcp-import.md), [archives.md](archives.md).

- **The content editor** (2026-11-17; owners only, the existing "Owners manage content items" RLS, nothing widened; mockup `docs/redesign/editor/`, Option A):
  - **Imported content is editable, and edits survive pack updates.** `content_items.edited` (jsonb, null = the pack's original) holds the campaign's version; `import_lcp` only ever writes `data` (`on conflict ... set data`), so an update never touches `edited` (pgTAP-tested in `supabase/tests/content_editor.test.sql`). `loadKind()` in `src/catalogue.ts` selects `edited` and hands every consumer `edited ?? data` as `data`, so every page sees edits with no other change. A check constraint keeps `edited->>id = id` and a name. The editor shows an **Edited** badge, a `Revert to original` action (sets `edited` to null after an "are you sure?") and an **Original** tab in the preview. The content page's update preview says how many of the pack's items have campaign edits and that they're kept (an info notice; `planLcp()` counts `edited`, and the page reads a cheap `edited->>id` alias, never the edit itself).
  - **New items go in one site-owned pack, `Campaign homebrew`** (`HOMEBREW_PACK`), made the first time an owner makes an item (`homebrewPack()` in `src/editorStore.ts`, a minimal valid manifest). Homebrew items live in `data` (not `edited`) and **start as drafts** (`content_items.draft`, default false): `loadKind()` leaves drafts out, so no picker, archive or sheet offers them (not secret, no RLS). `Publish item` (after an "are you sure?", only when nothing is unsaved) makes them live; a trigger (`private.keep_published()`) refuses a published item going back to a draft. Official items have no draft state.
  - **Saving is explicit** (`Save changes`, not autosave), because a save changes other pilots' sheets, and follows the site's save rules: every write ends in `.select()` through `checkWrite()`; `content_items`, `bionics` and `pilot_stats` have an `updated_at` (moddatetime) and updates are guarded with `.eq('updated_at', <raw string last loaded or saved>)`, so a newer save elsewhere shows `ConflictNotice` and stops saving; status via `SaveStatus` (`useSaveStatus`); `Discard changes` drops unsaved edits; `Save changes` uses the blocked pattern ("Fix 1 problem first."); leaving with unsaved changes asks first (route guard, in-page switches and `beforeunload`). `invalidateCatalogues()` runs after every write, so the rest of the site sees changes without a reload.
  - **"Used by":** `item_usage(item_id, is_bionic)` (owner-only `security definer`, same matching as `pack_usage`: the id as a quoted JSON string in a sheet or open change; bionics, being numbers in a list, are matched exactly) names the pilots. The pane shows "Used by WARDEN, LANTERN and 3 more. Saving changes their sheets." (a one-line info notice). `delete_content_item(id)` (owners only, refused while used, **homebrew items only**: official items are removed with their pack, or reverted) is a danger-zone `Delete item` with the blocked pattern while used. Bionics and personal stats have no delete (no grant, as before): a bionic is **retired**.
  - **Bionics** (a site table) save through `save_bionic(...)`, an invoker-security function, so the bionic and its stat bonuses save all-or-nothing and a stale save is refused; a bonus must point at a stat that exists (the foreign key; the form only offers existing stats, one bonus per stat).
  - **Page** (`src/views/ContentEditorView.vue`, `src/components/editor/`, route `/gm/content/editor`, `meta.owner`, `section: 'gm-content'`; linked as `Open editor` on the content page): the archives' list + pane machinery (`useListPane`, the `.list-pane` styles, `SheetTabs` for the kinds with counts, a search). Two tab rows (`TAB_GROUPS` in `src/contentEditor.ts`): a group row (not sticky, larger sentence-case tabs, no counts) then the kinds of that group (sticky, with counts). Mech content (Frames, Weapons, Systems, Weapon mods, Core bonuses, Manufacturers), Pilot content (Pilot gear, Talents), Combat rules (Rules, Actions, Tags, Definitions), Campaign (Biomods, Factions, Commendations). The group comes from `?cat=`; choosing a group opens its first kind. Rules, Actions and Tags are separate kinds (the Rules tab lists rules only); an old `?cat=rules&sec=tags|actions` link is redirected once (`oldLink`). Biomods, Factions and Commendations are site tables (wave 2, built on the faction pane's pattern, see [pilot-profile.md](pilot-profile.md)) (a faction is just a name, see [reputation.md](reputation.md); the list grouping by manufacturer is biomods only) (the personal stats tab was removed 2026-11-19: they're edited in the Supabase dashboard; the `pilot_stats` table and everything reading it stay). URL state `?cat=` and `?item=` (`new` for a new one). The list is a box per pack, Campaign homebrew first (always, with `New <kind>`), official packs showing 40 until `Show N more` (a search shows every match); rows show name, facts and a `Draft` or `Edited` badge. The pane (`EditorPane.vue`, keyed per item): a sticky bar (name, Draft/Published/Edited, status, `Discard changes`, `Publish item`, `Save changes`), then a quiet line for an imported item ("From {pack}." with `Revert to original` once edited; the bar's badge says `Official` or `Edited`, and `Published` is a plain badge), the one-line used-by notice and the problems (each with the word "Error" or "Warning"), the form (every section a `FoldPanel`), the danger zone, `Advanced: raw data` (under it, for every kind including site kinds, always starts folded), and beside it on wide panes (a container query at 54rem) the **live preview** (sticky only while it fits the screen, so a long one such as a frame's full information scrolls with the page and there's no scroll box inside the page; `ResizeObserver` in `EditorPane.vue`). **Desktop layout (2026-11-20):** the editor page has its own 120rem cap (not `--page-max`), the list is 18rem, the preview `clamp(24rem, 30%, 26rem)` and the form takes the rest (544px at 1280, 1152px at 1920); under 56rem nothing changed (`EditorPreview.vue`: Item card | Full information | Original), built with the site's own builders (`itemInfo`, `frameInfo`, `talentInfo`, `coreBonusInfo`, `bionicInfo`, `manufacturerInfo`, `ItemDetails`) from the unsaved form state. Phones: the list is a page, an item a page with a back link and Edit | Preview tabs.
  - **Every kind can also be edited through "Advanced: raw data"** (`RawDataField.vue`, a collapsed JSON box in mono sharing one object with the form; broken JSON is `--danger` with the word "Error" and blocks Save). **Forms exist for pilot gear, tags, core bonuses and bionics (phase 1), weapons, systems, weapon mods, talents and manufacturers (phase 2, 2026-11-17) and frames (phase 3, 2026-11-18, see [content-editor-forms.md](content-editor-forms.md))**: every kind now has a form. Validation is one pure module, `src/contentEditor.ts` (tested in `contentEditor.test.ts` and `contentEditorForms.test.ts`): the id must stay the same, a name is required, a gear type, tags that take a value (`{VAL}` in the name) need a number, bonus formulas must parse (`bonusValue`), damage must be a number or dice (`flatDamage`; the flat number is shown as "Players see 6 flat", never "average"), ranges and actions. Unknown tags, bonus ids and activations, and an action with no rules text (cards only draw actions that say what they do), are **warnings**, not errors. A new item's id is `hb_` + a kind code + the name's slug, unique-checked against every id and read-only (`newId()`); a **manufacturer's id is the short code you type** (`CHI`, letters, digits, `-`, `_`, `.`), fixed once created. **The first listed item opens by itself on desktop** (written once into `?item=` so a later search can't swap it under unsaved edits; phones keep the list page). **Problems carry the field they belong to** (`Problem.field`, a path into the data such as `profiles.1.range.0.val`): the list at the top stays, and the input also gets the danger outline, `aria-invalid` and an "Error: …" line under it (`Field.vue` and `FieldError.vue`, fed by `provideProblems()` / `useProblems()` in `useFields.ts`, so a form only names the path; a folded entry with a problem says "Needs fixing").
  - **Factions and commendations use `EditorPane` like every kind** (2026-11-24; `FactionForm.vue`, `CommendationForm.vue`; `FactionPane`, `CommendationPane` and `useSimpleEditor` are gone). Their rows save through `createItem` / `saveItem` / `deleteItem(key, kind)` in `editorStore.ts` (own tables, ids from the database, `updated_at` guard, `checkWrite`), validation is `problemsFor` (`ctx.others` = the other rows' names), and the danger zone, conflict notice, save bar and raw-data box are the pane's. No item-usage check for them: the delete is refused by the database as before.
- **The id rule:** an id is generated from the name and fixed once created (read-only in every form, `newId()`). The exceptions are manufacturers, whose id is the short code you type, and the site tables whose ids the database makes (biomods, factions, commendations).
- **Reusable fields** (`src/components/editor/`; the frame form is built from these too): `Field` (label, the input in its slot, a hint, the problem marking; `block` for rules text editors and radio groups), `FoldPanel` (a folding section panel, its title a step above the field labels (16px), with a one-line summary and "Needs fixing" while folded; every form's sections use it. Only Basics (Identity on frames) starts open, plus Range and damage (weapons, pilot weapons) and Stats (frames); open or closed is remembered per kind and section title in this browser through `src/fileSections.ts`, ids `editor:{kind}:{title}`, the kind provided by `EditorPane`; `forget` opts out, as the raw data box does), `RepeatList` (grouped entries as folding boxes, the first open, with up, down, remove and "Add", `fixed` for a talent's three ranks; the weapon's profiles, actions, deployables and ranks all use it), `ActionListField` (`ActionChip` beside the activation), `DeployableListField` (name, kind, size, HP, evasion, e-defence, armour, rules, its own actions; a `path` prop), `DamageField` (range or damage, `path` and `noun` props), `TagListField` and `BonusListField` (`path` props; only the ids the build maths counts, `BONUS_TYPES`, plus personal stats; a `replace` toggle; extra keys kept), `ChoiceField` (one of a few as real radio inputs: licence rank, mount size), `ToggleChips` (several of a list as neutral `aria-pressed` chips with a tick), `ItemIdListField` (existing items by id through `ItemPicker`), `ColourField` (hex text and a picker), `ItemBasics` (name, id, manufacturer, licence and rank, system points, a slot for more: shared by weapons, systems and mods), `ManufacturerField` and `LicenceField` (the manufacturer select, in the item, frame, core bonus and biomod forms, and licence plus rank, in items and frames; the select always ends with the built-in **Exotic** option, id `EXOTIC`: `EXOTIC_MAKER` in `src/archive.ts`, a constant and not a content row), `RawDataField`, `EditorPreview` (the border is a manufacturer's own colour, never lilac) and `useFields` (typed accessors over one data object that's replaced whole on every change). Rules text is `RichTextEditor` with the `html` prop (the value is the HTML string game data uses) and the same full toolbar as every editor; on display `src/rulesText.ts` keeps only the allowed sizes, `#rrggbb` colour, glitch, game icons and h3, and drops everything else. Inputs and selects in `.ed-form` fill their field's width (`style.css`).
- **List by manufacturer (2026-11-21):** frames, weapons, systems, weapon mods, core bonuses and biomods list in a box per manufacturer (`BY_MAKER` in `ContentEditorView.vue`: logo, count, `--mf` top border, `Other`, Exotic last; an edited item's `edited.source` moves it), with `New <kind>` above the boxes, and `Show N more` per box (`expanded` is keyed by box). Pilot gear, talents, tags and manufacturers stay a box per pack, factions and commendations one box. The row no longer repeats the manufacturer.
- **Effects, requirements, equipment (2026-11-21):** `BonusListField` is now the **Effects** field: any stat or `EFFECT_BONUS_TYPES` effect (mounts, structure repair cost, drone and deployable numbers, weapon range, threat, damage and added tags, overcharge heat), a value that fits the type, and under `Options` the weapon filters, `max` (add_mount) and `Sets the base`. Only what lasts out of combat and shows on the sheet is edited; in-combat and conditional effects belong in the rules text (2026-11-21 overhaul). There is no `Only when`, weapon-size or damage-type input (nothing official or local uses them); rows that carry `condition`, `weapon_sizes` or `damage_type` keep them untouched, a conditional row is still never counted. Lists key their rows by a stable id (`useRowKeys`), so rich-text editors and fold state follow the row on remove or move, and `RichTextEditor` takes a changed model value (and label) from outside. `RequirementListField` (a `Requirements` fold, last, on every kind but tags, manufacturers and the site tables except biomods) writes `requires`; `GrantFields` (built in, optional, `Replaces the frame's built-in weapons.`) is on core bonuses, systems, biomods, frame traits and core systems (talent ranks have the checkbox). Pickers show the unmet requirement as the blocked reason `Needs Brawler II` (`unmetRequirements()` / `requirementReason()` in `rules.ts`): pilot gear, talents, licences, core bonuses and the mech page's frame picker, next to the mech loadout's.
- **Definitions tab (2026-11-24):** `?cat=definitions&item=<list key>` edits the 12 small game lists in `game_definitions` (`DEF_KINDS` in `src/definitions.ts`: label, noun, box, and which fields a list has). The list column shows four boxes of lists with entry and hidden counts (`loadDefinitionFacts`); `DefinitionPane.vue` (keyed per list) edits one list as a whole: `RepeatList` rows with move up/down (the order is `sort`), label, id (made from the label until typed in, fixed once saved), icon, colour (only the game's own `--dmg-*` / `--act-*` names), mount slots and hint, and Hidden. A saved row has no Remove (`removable` prop on `RepeatList`): hide it or `Delete`, which goes through `delete_definition` and is refused while used. One `Save changes` sends the new or changed rows through `save_definitions` (`saveDefinitions` in `editorStore.ts`, all or nothing, each saved row guarded by its raw `updated_at`). Pure rules (ids, problems, payload) are in `src/definitionEditor.ts`. The pane bar styles moved to `style.css` (`.editor-pane .bar`), shared with `EditorPane`. After a write, `invalidateCatalogues()` and `loadDefinitions()` refresh the pickers.
- **Effect registry (2026-11-24):** every effect type is one entry in `BONUS_REGISTRY` (`src/bonuses.ts`): id, label, picker group, value kind, scope (pilot or mech), how it is counted (`stat` with its mech stat key, `pilot`, or `effect` read by its own code), filters. The editor picker (`bonusTypesFor`), validation (`problemsFor`), the one-line summary (`bonusSummary`), `isPilotBonus` and the mech sheet maths (`mechEffects`) all read it. **To add a mechanic: add one entry** (a stat the mech counts needs only its `stat` key; a new effect also needs its code in `mechData.ts`). Personal stats come from `pilot_stats` through `personalDef`, so an owner can add a stat and use it as an effect with no code. An id that is not in the registry is kept, shown on the sheet as a reminder (`bonusReminder`) and warned about in the editor ("shown on the sheet but not counted"). Pilot ids that start `pilot_` but are not declared are still treated as the pilot's and are not reminded.
- **Core power checks (2026-11-24):** a frame's core power can ask for check modifiers through `core_system.check_bonuses`, a list of `{ id, accuracy: 1 | -1, val: 0 }` (id one of hull, agility, systems, engineering, tech_attack). `coreCheckBonuses()` in `src/coreRules.ts` reads the field first (an empty list means none, a non-list is ignored) and falls back to `CORE_CHECK_BONUSES` for official frame ids, so `mechEffects` is unchanged for official frames. The table stays: it is the default for the official frames and still keys the four core bonuses (`cb_*`) read in `mechEffects`. The `Core power checks` fold in `FrameForm.vue` shows the built-in list until edited, then writes the frame's own field. It is its own small row editor, not `BonusListField`, because the effect picker has no accuracy input or check types. Validation is in `checkFrame` (`contentEditor.ts`).

- **Phase 4b (2026-11-24):** weapons get the `Equipment` fold (`GrantFields`; `checkWeapon` already checked it, and `talentGrants` reads equipped weapons). Mods and pilot gear get **no** grants: the sheet never reads them there (`mechData.ts` `granting` is weapons and systems only). Biomods can't store actions (the `bionics` table has no actions column) and core systems wait for the frame form's owner. The effect field has a search box (`Search effect types`, narrows every row's picker, a row keeps its own type, Add starts from the first match) and a plain `bonusSummary` line under each row. **Duplicate** (pane bar, `DUPLICABLE` kinds, `duplicateItem` in `contentEditor.ts`): a new unsaved item with a new id and `Copy of X`, opened through the view's `copy` ref. **Used by** for items: `referencesTo(id, rows)` scans the loaded `REFERRING_KINDS` rows (cached `loadKind`) for any value equal to the id, shown under the pilots line. Biomod references are not scanned.
- **Phase 4b, core system requirements (2026-11-24):** not added. Nothing reads a core system's requirements: `unmetRequirements` runs on the frame itself (`MechView` frame picker, `f.raw`) and on items, and `rules.ts` never reads `core_system`. The frame's own `Requirements` fold already gates the frame and its core system.
- **Export and import of actions and rules (2026-11-24):** the homebrew `.lcp` carries published `actions` and `rules` rows (`writeLcp` writes every `LCP_KINDS` file) and the importer reads them back, checking each with `validateItem` and requiring an `hb_` id (see [lcp-import.md](lcp-import.md)).
- **Hidden takes effect (2026-11-24, phase 7c):** `hidden` (`data.hidden`, `edited.hidden` for official items, `organisations.hidden`, `commendations.hidden`; biomods keep `retired`) means "not offered", never "gone". `loadKind` and the `useMechData`/`useGameData` lists still return hidden rows, so every lookup by id (a pilot's owned weapon, frame, gear, talent) keeps working and the editor sees them. `to*` (`toItem`, `toFrame`, `toTalent`, `toCoreBonus`) set `hidden: true`, and pickers/lists drop them with `offered(list, keep)` (`src/catalogue.ts`; `keep` spares the current choice): the buy and slot lists in `PilotLoadout`, the weapon/system/mod picker in `MechLoadout`, the frame picker in `MechView`, licences and talents in `RankPanel` (via the option's `hidden`), `CoreBonusPanel`, and the archive entries. `loadCommendations` (the award picker only) filters `hidden = false`, `ReputationPanel` keeps a hidden faction only where the pilot has a level, and the editor loaders and `createItem`/`saveItem` carry `hidden` for factions and commendations (UI in 7d). Tests: `src/hidden.test.ts`.
- **Hidden tick and Saved by line (2026-11-24, phase 7d):** `EditorPane.vue` shows one "Hidden from players" tick for every kind without its own (not tags, actions, rules, biomods): it sets or removes `working.hidden`, so the normal save stores it (`edited.hidden` for official items, `data.hidden` for homebrew, the column for factions and commendations) and Revert to original still works. Biomods keep `retired`, relabelled "Hidden from players", and their list row now shows the Hidden badge. "Saved by NAME, date" is one quiet line from `loadSaveLine` (`content_saves`, owner-only; `loadListSaveLine` takes the newest stamp of a Definitions list), reloaded after a save. `Unlock.hidden` (`info.ts`) stops `UnlockList` linking a hidden item to an archive entry that isn't listed: it opens its information instead. Browser pass not done yet.
