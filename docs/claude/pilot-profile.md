# Pilot profile

Covers: Cosmetic pilot profile: colour, motto, banner, gallery. Saves live with no GM approval.
See also: [service-record.md](service-record.md), [id-card.md](id-card.md), [dossier-page.md](dossier-page.md).

- **Pilot profile customisation (2026-11-20, wave 1 of 2; migration `20261120090000_pilot_profile.sql`, tested in `supabase/tests/pilot_profile.test.sql`; on the hosted project):** cosmetic and **public to every logged-in user**, and it **saves live with no GM approval, even on approved pilots** (game parts still go through changes). A pilot's own player writes it unless the pilot is dead; GMs and owners write any (GM edit mode in the UI).
  - **Table `pilot_profiles`** (one row per pilot, `character_id` primary key, cascade): `colour` (`#rrggbb`, check constraint), `motto` (at most 120), `banner_image` (an upload path, the same shape check as `pilot_image`), `gallery` (jsonb array of at most 4 `{path, caption}`, paths in the upload shape, captions at most 140: a trigger, `private.check_pilot_gallery()`), `updated_at`. Players insert and update (never delete); GMs and owners insert, update and delete. The uploads use the existing `character-images` bucket policies unchanged (own folder in, own folder or GM anywhere out).
  - **Motto** is now a growing, wrapping textarea (Enter leaves it) instead of a one-line input, so long mottos don't clip on phones.
- **UI** (`src/pilotProfile.ts`, `usePilotProfile(characterId)`; used by `PilotManageView.vue`): loads the row (`ready` stays false if the read fails, so nothing is saved over an unseen profile); each save sends the whole profile as it is on screen, one at a time; the first save is an upsert, later ones update with `.eq('updated_at', <raw string>)` through `checkWrite()` and set `conflict` (the page's `ConflictNotice`) when someone else saved first; failures keep the edit and `Retry` re-sends. Images no longer used are deleted best-effort after a successful save. `profileEditable` in the page is separate from the sheet's `editable`: your own living pilot (any status, so approved pilots too) or a GM in edit mode.
  - **Header:** the banner (`ImageUpload` with `noun="banner"` and `BANNER_SIDE` 1600, the only image bigger than 1024px) is the cover's top strip (9rem, 6rem on phones, `object-fit: cover`, fading into the panel at its foot, the pilot colour as a 2px line under it; uploaded in the cover's tools while editing); the motto sits under the name in italic `--text-dim` between quotation marks in the pilot colour (drawn by CSS, not stored; an inline field while editable, saved on leaving it); the cover's top border is 3px in the pilot colour.
  - **Banner position** (migration `20261120110000_banner_position_and_public_card.sql`; on the hosted project): `pilot_profiles.banner_x` / `banner_y` (0 to 100, default 50, the banner's `object-position` in percent) and `banner_zoom` (1 to 3, default 1, a `scale()` from that point). Saved with the rest of the profile; a new or removed banner resets them to centred (`BANNER_CENTRED`). Set with `Position banner` (see [dossier-page.md](dossier-page.md), Cover).
  - **Colour field** (the cover's tools): `PilotColourField.vue` (hex box and colour swatch joined as one `.colour-input` control, with `Reset colour` beside them; the sheet previews the picker live and saves when you let go or leave the box).
  - **Gallery** (`PilotGallery.vue`, 08 Gallery): up to 4 thumbnails (4:3, `object-fit: cover`, four across, two columns on phones), each a button opening the full picture and caption in a `dialog.dialog`; editable: `Add picture` (hidden at 4, "4 of 4 pictures" in dim text), per picture a caption field, `Replace` and `Remove`; read-only viewers get no section when there are none. Gallery list changes are the pure functions `addPicture`, `replacePicture`, `removePicture`, `setCaption` (tested).
  - **Registry cards:** `PILOT_FIELDS` embeds `profile:pilot_profiles(colour)` so the cards load in one query, and `PilotCard` takes `colour` (a 3px top border). The GM queues' cards don't use it yet. Wave 2 adds a commendation count ([service-record.md](service-record.md)).
  - **Colour, in the page:** the sheet root gets `--pilot` (and `.has-pilot`) when a colour is set. It also gives the profile panels a 3px top border and the gallery's hover/focus outline and dialog border.
