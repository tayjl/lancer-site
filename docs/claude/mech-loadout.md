# Mech loadout

Covers: The mech loadout (mounts, systems) and weapon mods.
See also: [mech-page.md](mech-page.md), [item-cards.md](item-cards.md).

- **The mech loadout** (`src/components/MechLoadout.vue`) uses the same cards: a system points `.meter` at the top ("All used.", "2 left", red "1 over"), then one slot per mount the frame gives (in its order, labelled "Main mount" and so on), then the systems, with `Add system` in their heading. Mount rules (`allowedSizes()` in `src/mechData.ts`, tested in `src/mechData.test.ts`): Main takes Main or Auxiliary; Heavy takes any size; Main/Aux takes a Main and an Auxiliary; Aux/Aux two Auxiliary; Flex one Main or two Auxiliary. An empty mount is one empty state saying what it takes ("Takes one Main or two Auxiliary weapons.", `MOUNT_HINTS`) with `Add weapon`; a mount with one of two places filled shows the weapon's card and a smaller empty state for the other. A **Superheavy** weapon also takes the first other empty mount, whose empty state reads "Bracing the Superheavy weapon." (`bracingMount()` in `src/rules.ts`); the picker blocks it when no mount is free. Weapons and systems both cost system points. The pickers block (disabled button, reason beside it): items the pilot's licences don't cover ("Needs IPS-N Drake II"; listed after the unlocked ones), anything over the system points, a second copy of a Unique item, and AIs over the build's capacity. **Integrated** weapons and systems (built into a frame, e.g. the Sherman's) show as "Integrated mount" / "Integrated system" cards that can't be removed and cost nothing; talent-granted integrated items appear automatically and optional special equipment is offered only while unlocked. Effective mounts include permanent core bonus choices.
- **Weapon mods** (2026-11-17; rules in `docs/lancer-rules.md`): lancer-data's `mods.json`, content kind `mods` (a mod is a `toMod()` `Item` of type "Mod"; `LCP_KINDS`, core content, the local seed and `import_lcp`, migration `20261117190000_weapon_mods.sql`, on the hosted project; `Load core content` comes back for an install without them). **Stored** per weapon place in `sheet.mechs[id].weapon_mods` (`"mount:place"` to mod id, only a mod id; old sheets without it work); `fittedMods()` / `weaponAt()` in `mechData.ts` say which mods sit on a weapon that's there (the rest are stray: they count for nothing, the rule check names them, and `Mods without a weapon` offers `Clear unfitted`). **One per weapon, on a mounted weapon only** (not frame- or talent-integrated ones, not the Integrated Weapon mount, not a `no_mods` weapon: `modsRefused()` / `modBlockedBy()` in `equipment.ts`). The mod sits **inside its weapon's card** (`BuildItem.vue` passes `ModSection.vue` into `ItemDetails`' `mod` slot): under a thin `--rule` line, a small system-green square with the mod symbol (`mod.svg`, COMP/CON's weaponmod), its name (an `InfoButton`), its SP at the right, then `ItemBody.vue` (the card's body, shared with `ItemDetails`: facts "IPS-N Nelson II · Mod for Melee", rules text, actions, tags); while editable `Swap mod` and `Remove mod`, or the empty state "No mod." with `Add mod` (read-only sheets show a mod, never the empty state). The picker (`MechLoadout.vue`) lists every mod, blocked ones (the licence, wrong weapon type or size, a second Unique, AI capacity, SP) with the reason beside a disabled `Choose`. `equipmentDetails()` takes the weapon's mod: added range and tags change the weapon's numbers and tags (named under "Where these numbers come from"); added damage is conditional (Thermal Charge needs a hit and a charge), so it is never counted and stays in the mod's rules text (developer, 2026-11-17); a mod's `bonuses` count through `mechEffects()` like other equipment; its SP counts in the meter, the plate and `mechProblems()`. The licence ladder (`licenceUnlocks()`) and the archives (category `weapon mods`, listed by licence like systems) include mods. Change review: "Mod on Assault Rifle: Nanocomposite Adaptation" in the mech's weapon-mounts group (`changeDiff.ts`).
- **Superheavy mount (2026-11-21):** a mount type that takes only Superheavy weapons. The weapon still needs a second empty mount (`bracingMount()` in `src/rules.ts`): the frame's Heavy mount if it has one, else any other empty mount. Blocked reason: `Needs an empty mount`.
- **Mount choices (2026-11-21):** "Core bonus assignments" also lists every `replace_mount` bonus on the mech (`mountReplacements()`), labelled by its source's name, stored in `core_mounts` under the source's key. `mechEffects()` returns the built `frame`; the page reads it from there.
