# Pilot inventory

Covers: Pilot gear: slots, owned and equipped gear, Buy item, View inventory, and the loadout UI.
See also: [levelling-and-manna.md](levelling-and-manna.md), [item-cards.md](item-cards.md), [pickers-and-info.md](pickers-and-info.md).

- **Pilot equipment:** only LANCER pilot gear (armour, weapons, kit) from the game data. No free-text items.
  - **Slots** (decided by the developer, 2026-10-29): **1 armour, 2 weapons and 3 gear**, laid out like COMP/CON's loadout.
  - **Inventory** (decided by the developer, built and pushed 2026-11-20, the migration is dated 20261121; migration `20261121110000_pilot_inventory.sql`): pilot gear is **owned** once bought (`sheet.owned_gear`, one entry per copy with its own key and description; duplicates allowed) and equipped by key (`sheet.equipped_gear`). **Equipping needs no approval**, even with a change open (`equip_pilot_gear`). **Buying goes through a change** and costs the item's price (`manna_cost`, set by owners in the content editor; 100 when unset). A new pilot's **first full loadout is free** (1 armour, 2 weapons, 3 gear; `freeGear()` in `src/rules.ts` mirrors the database's `settle_pilot_gear`). **No refunds:** players can't remove owned items; GMs can. UI: the loadout section below.
- **The loadout** (`src/components/PilotLoadout.vue`) is six slots in one three-column grid (a plain grid, not `.slot-grid`; cards top-aligned, so a tall one never stretches the others): Armour, Weapon, Weapon on the first row, Gear, Gear, Gear on the second, each card under its own small uppercase type label (`SlotCard`'s `label`), so the type never depends on position; on phones (under 64rem) one column in the same order, with the biomods in their own row under the loadout. Empty slots show the empty state ("No gear yet." with `Add gear`); read-only sheets skip them, so the filled cards close up in order ("No pilot gear." when all are empty). Each `sheet.owned_gear` entry is `{ key, id, notes?, damageType?, free? }` (`free` is set by the database only; it replaced the old `pilot_gear` and `pilot_gear_notes`, which the migration converted onto owned items); `equippedGear()` and `loadoutSlots()` in `src/gameData.ts` sort the equipped items into slots by `type`, each type in equipped order. While the pilot can equip, each card's foot has `Swap` and `Remove`. **Approved pilot** (own, or a GM in edit mode; even with a change open): a slot's picker offers its owned, unequipped items of that type (their description as the dim line); choosing equips and `Remove` unequips, at once and with no approval, through `equipGear()` in `src/myPilot.ts` (`equip_pilot_gear`; only keys of known Armor/Weapon/Gear items are sent); save status as usual. Under the slots (approved pilots only), one folding toggle `Stowed {n} · Misc {m}` (chevron, lilac only on hover and focus, closed by default; hidden when nothing is stowed, there are no misc items and the viewer can't add any). Opened: **Stowed** = owned items not equipped (equipped ones are only in the slots), as plain one-line text rows, no cards, grouped Armour / Weapons / Gear / Misc with the small uppercase label in a narrow left column (above the rows under 36rem); only groups with rows show, plus Misc for a GM in edit mode. A row: the item's symbol (`itemCard()`'s icon), its name, then dim on the same line `Bought in this change · {price} manna` or its description in quotes, cut off with an ellipsis; items of other types or in no loaded pack go in Gear, the latter as `Unknown item ({id})`. A row is a button (`aria-expanded`) that opens it in place, one at a time: the price line, its `Description` (`ItemNote`, editable in a change), `Info` (the full information) and the GM's `Remove`, with `Not removed: …` there. `Buy item` is in the Loadout heading row. An item bought in the open change has its slot-picker row blocked "Needs GM approval". **Misc items** (`sheet.misc_items`: `{ key, name, notes? }`, GM only, the database refuses player changes) are free-text: name and description, never equipped, no price; only a GM in edit mode gets `Add misc item` (a small text button at the end of the Misc group; an inline form: `Name` required, max 60; `Description` max 140; `Add item` / `Discard changes`) and `Remove` in the opened row (same confirm as owned items). `Buy item` (change or GM edit mode) opens every pilot gear item with its price (`gearPrice()`: the item's `manna_cost`, 100 when unset), in three boxes, Armour, Weapons and Gear (`PickGroup.fixed` in `src/pickerRows.ts`: the boxes keep their order even when nothing in one can be bought), with the manna balance in the picker's bar; rows are blocked "Not enough manna" or by the GM-only/Exotic rules; choosing adds a new copy (`crypto.randomUUID()` key), unequipped. Players can't remove owned items; a GM in edit mode can (`Remove`, then "{Item} will be taken off this pilot. This can't be undone." / `Remove item`). **Pilot being created** (pending): a slot picks from the whole catalogue and adds and equips a new copy in one step, `Remove` takes it off the sheet, and each card says `Free` or its price (`freeGear(…, null)`: the first 1 armour, 2 weapons and 3 gear are free). **Variable damage:** a Variable weapon (a Signature weapon) needs a damage type (`DAMAGE_CHOICES`) whether it is equipped or stowed: `Damage type` select (`Choose…` until picked) on its slot card and in its opened stowed row (`setDamage()` in `PilotLoadout.vue`, saved on `owned_gear[].damageType`), and the rule problem "{Name} needs a damage type." (`pilotProblems` in `src/rules.ts`) until then. Live pilots who already owned a Signature weapon when this shipped show that problem until they choose one through a change (the developer decided to leave this, 2026-11-20). Dead pilots: read-only. Unknown ids are kept and counted.
