# Registry

Covers: The registry: pilot cards, search, opening a record and GM edit mode.
See also: [pages-home-lore.md](pages-home-lore.md), [dossier-page.md](dossier-page.md), [gm-pages.md](gm-pages.md), [approval.md](approval.md).

- **registry** (`src/views/RegistryView.vue`) is a centred grid of pilot ID cards (scoped `.id-grid`: one to a row on phones, two or three on desktop), with the count of pilots in the header. **Three lists in one page** (2026-11-21): underline tabs (`SheetTabs`) Approved (default), Pending (submitted, waiting on a GM) and Memorial (dead), kept in the url as `?list=pending` / `?list=memorial` and switched with `router.replace`. `/pending` and `/memorial` redirect to them. `pilotList()` in `src/router.ts` gives a record's breadcrumb its list's link.
  - **Search** (2026-11-15): a box above the cards filters the loaded cards by callsign, pilot name or player name (2026-11-21: no longer mech names, which the card doesn't show); every typed word must match (`pilotMatches()` in `src/pilots.ts`, tested in `src/pilots.test.ts`). It shows "x of y pilots" (dim, mono numbers) while filtering, and is hidden when the list is empty. A failed load shows a `.notice.warn` with the error.
  - **The card** (2026-11-21): each pilot's Union ID card (`PilotIdCard.vue`, see [id-card.md](id-card.md)), the whole card a link to the record (its name is the card's label); no panel or border around it (the developer, 2026-11-21); hover and focus give it a lilac glow that follows the cut corners (`drop-shadow`), plus the focus ring on focus. No `Download card` (no `extra` passed) and no silent save (no `savePath`) here. Under it, centred and dim, "Player: x" (or "Unknown player"). Dead pilots need nothing extra: the card's Status says DEAD. Each link has `content-visibility: auto` so off-screen cards aren't drawn. The same card and grid serve pending and memorial (route `meta.status` picks the pilots, `meta.empty` is the text when there are none). `PilotCard.vue` is now only the GM queues' card.
  - **Clicking a card** opens the pilot record (`/registry/:id`). For visual congruity (the developer's request, 2026-10-29) **it's the my pilot page itself, read-only** (`PilotManageView.vue` with a route `id`), so a record always looks exactly like your own sheet. Its mech cards open the mech page read-only too (`/registry/:id/mechs/:mechId`, `MechView.vue`). The back link goes to the list the pilot is in.
    - `useMyPilot(id)` in `src/myPilot.ts` loads that pilot instead of yours, never editable. The `characters` select embeds `character_sheets`, which RLS only gives to the pilot's own player, GMs and owners; for everyone else (the embed comes back empty) it calls `pilot_sheet()` for the sheet without the backstory and manna, plus level, so every section shows for every viewer. `canSeeBackstory` (renamed from `canSeePrivate`; also exported as `canSeeManna`) says whether the whole row came back: only then the Backstory panel shows the real backstory (and its toggle) and the header shows manna; otherwise only a public copy of the backstory, if there is one, and no manna (the page treats the balance as unlimited so the rule check can't raise a false overspend; every price tag and balance block is editable-only anyway). Editing is unchanged: only the pilot's player (pending pilot or draft change) and GMs in edit mode.
    - GMs get a `GM review` link (pending pilots only) to the review page, in the header. The decision itself is never on the record. They also get an `Edit as GM` button (not on dead pilots): **GM edit mode**, below in this file.
    - **GM edit mode** (`?edit=1`, kept with `router.replace`; the record, the review page and the mech pages; `useMyPilot(id, { gmEdit: () => route.query.edit === '1' })` in `src/myPilot.ts`). Turns on `editable` for GMs and owners on any living pilot (pending or approved), so the sheet and mech pages are the same components a player uses on their own pending pilot, and every save goes straight to the pilot's `characters` / `character_sheets` rows (never a draft change), through the same save queue. `gmEditing` is false for non-GMs (a hand-typed `?edit=1` does nothing) and for dead pilots. **It works on a GM's or owner's own pilot too** (2026-11-19), so they can give their own characters Exotic gear (the only place Exotic can be picked): on My pilot an approved pilot's header has an `Edit pilot` button that opens their own record in edit mode (`/registry/:id?edit=1`; a pending one is already editable); it saves straight to the pilot, never to a draft, and the usual "change waiting" warning applies if their own draft change is open. **Exotic content can be picked only here** ([content-editor-forms.md](content-editor-forms.md), The Exotic Gear tag). Mech cards and the mech breadcrumb keep `edit=1`. `GmEditBar.vue` (a bar joined to the header's foot, on the pilot and mech pages): a `GM edit` badge, "Saves go straight to this pilot. Rules and prices are off.", the save status and `Done`, and (pilot page only) a rewards row under a hairline (`GmRewards.vue`); with a `.notice.warn` when the player has a change open (`waiting`, loaded for GMs in edit mode), linking to it once submitted. A direct edit blocks that change from being approved (the "changed since" check, see [approval.md](approval.md)), by design: review it first. Sheet saves keep `sheetUpdatedAt` current, so approving a pending pilot after editing it isn't refused. Level, manna and experience are in the bar's rewards row. **Rules and prices are off** (2026-11-21): pickers drop blocked reasons and prices (`useGmOverride()`), and everything a GM adds is a free **GM grant** (`character_sheets.gm_grants`, recorded by `useMyPilot`; `mannaSpent` skips them) shown with a `GM grant` badge (shield plus words; dashed rank pips on licences and talents). The rule check still lists problems, as a warning. A GM in edit mode can edit and delete any service record entry. Also in edit mode: a `GM only` section (reputation, commendations, reward history) and the danger zone.
    - `App.vue` keys the `RouterView` by path, so going from one record to another loads the new pilot.
  - **Real data:** `fetchPilotCards()` in `src/pilots.ts` calls the `pilot_cards(target_status)` database function (security definer: level and licence level come from `character_sheets`, which other players can't read; nothing private), through `fetchAll()` (ordered by the list's date then id). It returns the card's fields plus the dates and the player's name, filtered like the old query (pending = submitted only, oldest first). `PILOT_FIELDS` and `PublicPilot` stay for the GM roster and the record pages.
