# Ui principles

Covers: Redesign direction and design rules: readability, one colour per job, alignment, density, mockup.
See also: [colours-and-type.md](colours-and-type.md), [buttons-and-dialogs.md](buttons-and-dialogs.md), [layout-and-nav.md](layout-and-nav.md).

- **Readability and usability come first** (the developer, 2026-11-16). This rule outranks everything else in this section:
  - Everything should be **readable at a glance**: the same kind of thing always uses the same symbol and colour, so players can tell what something is without reading the words. Each colour has **one job**, and colour is never the only signal (always a symbol or word too).
  - **Standardised and clean:** one way to draw each kind of thing (button, card, tab, stat, tag, notice), reused everywhere. Compare against COMP/CON, LANCER's own app, for how game things are usually shown, and follow its conventions unless there's a reason not to (without copying its code).
  - The **terminal styling is flavour, not structure.** Where it costs readability or usability, drop it.
  - **The site-wide redesign** (2026-11-16) covers every page except the login screen, which stays exactly as it is. All phases are built: 1 (the foundation: tokens, type, base controls, icons, top bar, section tabs), 2 (shared content components), 3 and 4 (the pilot sheet and mech page, archives), 5 (registry cards, GM pages), 6 (content page, writing editor, confirm dialog, portraits) and 7 (a site-wide consistency pass). Where any page detail in these docs conflicts with this rule, this rule wins.
- **Redesign direction** (the developer's answers, 2026-11-16):
  - **What's wrong now:** monospace text everywhere, colours that carry several meanings, terminal decoration (`[ brackets ]`, `> label // private`, `// empty //`, all-lowercase), and layout/density (stacked sticky bars, centred text and lists, hard to scan).
  - **Flavour: a light touch.** Dark theme, the HORUS logo and the accent colours stay. Everything else looks like a clean game app in the spirit of COMP/CON. Terminal touches only in the logo, the home page and small details such as empty states.
  - **Labels: COMP/CON style.** Short UPPERCASE labels in a readable sans font (Atkinson Hyperlegible Next), normal sentence case for anything read, and numbers in the monospace font so they line up. No `>` prompts or `//` tags.
  - **Colour: one job per colour, following COMP/CON's conventions closely.** The interface accent (lilac) only marks things you can click and where you are. Status colours are separate (OK/added, pending, danger/dead/removed). Teal (`--gm`) marks GM and owner tools only: ways into GM modes (`.gm` on a button or link, label always says "GM") and the `.private.gm` "GM only" / "Owner only" tags; buttons inside GM screens keep their meaning colours. Game meanings (damage types, action types, ranges, manufacturers and so on) use COMP/CON's colours and symbols, always with a symbol or word as well.
  - **Player customisation exception** (2026-11-20): the one-job-per-colour rule doesn't apply to a pilot's own colour (`--pilot`), but it is decoration only: borders, bars and outlines on their sheet, gallery and card. Never a button, link, tab, status, icon meaning or text colour. `displayColour()` in `src/pilotColour.ts` (tested) lightens a colour that is too dark: it mixes the stored colour with white in 5% steps until it has at least 3:1 contrast with `--panel`, so it also shows on `--void`; stored values stay as picked. Always read `--pilot` through `displayColour()` and never as stored.
  - **Identity colour** (the developer, 2026-11-20): a page's identity colour (the pilot's `--pilot` on the pilot page, the maker's `--mf` on the mech page) gets the same amount of colour on both: the header (pilot: banner gradient, portrait brackets and the cover's small rules; mech: the plate's logo, 3px top border and faint band) the section-title dashes and the stat tiles' top strip. Nothing else on the page: not the file index (its marker is lilac, it's interactive), not charts or radars, item cards, text, buttons or icons. Outside these pages the maker colour stays the logo and a 3px top border (hangar cards, information dialogs).
  - **Alignment: left-aligned** for anything read at length or compared down a column (lists, rules text, tables), so the eye has one starting edge. **Important, singular showcase things are centred** (the developer, 2026-11-16): mech cards in the hangar, stat tiles, numbers in boxes, empty-state messages, manufacturer cards.
  - **Archives layout (decided 2026-11-16): list + detail pane**, like COMP/CON's compendium, replacing the cluttered rows: on desktop a slim list of names grouped by manufacturer/licence with one or two key facts, and the selected entry's full card beside it; on phones the list, with tapping opening the entry.
  - **Density: compact, like COMP/CON**: more on screen, tighter cards and gaps, text still a comfortable size.
  - **Devices: phone and desktop equally.** Every page works fully on both.
  - **Process:** an audit of the current UI, then a static **mockup** (pilot sheet, mech page, an item card) for the developer to approve, then the shared components, then the pages rebuilt one at a time.
  - **Mockup approved** (the developer, 2026-11-16: "exactly the direction I meant"). **The reference for every redesigned page is `docs/redesign/prototype/`** (`index.html`, `styles.css`, `icons.svg`; open it through the dev server at `/docs/redesign/prototype/index.html`, sections `#legend`, `#pilot`, `#mech`, `#mech-gms`, `#items`). The developer's copy is the private design canvas https://claude.ai/artifact/R6GikboW5BhycsmD49RuuY. What it settles:
    - **Colour jobs** (the legend's table is the source of truth): lilac = interactive only; status `--ok` (approved, saved, added), `--wait` (pending, draft; draft dashed), `--danger` (rejected, rule broken, removed, over budget, destructive), dead = dim with a skull, `--info` (neutral notes); COMP/CON's damage-type colours (icons only), action/activation colours (clipped chips, chip before the action's name, actions always shown in full), item-type header colours (weapon grey, system green, frame/licence purple, pilot gear/bionic teal, talent brown, core bonus lime with dark text); manufacturer colour only as the logo and a 3px top border, never text or a tint, except the mech page's header band (see Identity colour below).
    - **Symbols:** an SVG sprite drawn in `currentColor`: the existing LANCER stat/range/damage icons, COMP/CON's cci icons (GPL-3.0) and Lucide (ISC, needs a README credit). Proposed symbols accepted: HASE (hull anvil, agility wind, systems chip, engineering wrench) and personal stats (physicality dumbbell, dexterity hand, perception eye, acuity lightbulb, tech-fluency code brackets).
    - **No dark inset boxes** (the developer, 2026-11-16): actions, deployables, frame traits, core powers and talent ranks inside a card or the information dialog sit on the card's own surface, separated by spacing and a thin `--rule` line; the action chip and bold name mark where an action starts. No `--void` sub-panels inside cards (stat tiles excepted).
    - **Patterns:** only GM-only and owner-only sections carry a lock tag (the developer, 2026-11-19: "remove the private tags from everything except backstory, where players can toggle it on/off"); the pilot sheet, mech page, loadouts and rank panels show no "Private" tags (all of that is public now; the backstory's toggle ([backstory.md](backstory.md)) is the one place a private state is drawn); a blocked action is a disabled button keeping its label and cost ("Raise rank · 600") with the reason beside it in secondary text; item names are buttons that underline on hover/focus; one empty-state look; stats are tiles on desktop and one-line rows (icon, name, value, − / +) on phones; tab rows scroll sideways with a fade cue on phones; the slim top bar stays fixed on phones too.
