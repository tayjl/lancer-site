# Stats

Covers: Pilot stats (combat, personal, HASE), mech stats, permanent build effects, rules text and the no-dice rule.
See also: [levelling-and-manna.md](levelling-and-manna.md), [dossier-sections.md](dossier-sections.md), [mech-page.md](mech-page.md).

- **Pilot combat stats (updated 2026-10-29):** HP 6, armour 0, speed 4 and **e-defence 10** before permanent equipment/talent/core bonuses. **Pilots have no evasion** (latest developer correction); ignore `pilot_evasion` bonuses and omit them from equipment cards. Keep pilot e-defence and normal mech evasion. **Grit is shown** (the developer, 2026-11-19): a Grit tile in General stats, half the level rounded up, display only (nothing uses it). No save target or sensors. Stats are public (2026-11-19), calculated and have source disclosures.
- **Pilot stats are custom.** LANCER's skill triggers ("narrative triggers") are replaced by five homebrew stats: **physicality, dexterity, perception, acuity and tech-fluency**.
  - Each **base stat starts at 2**, with **4 shared points** to allocate. Base stats stay within **2–4** and don't gain points with level. Biomod modifiers are applied afterwards and can take effective totals below 2 or above 4. Existing saved allocations are not silently rewritten: out-of-range or overspent bases are flagged for correction (developer's request, 2026-10-29).
  - They're public to every logged-in user now (2026-11-19, see [pilots.md](pilots.md)).
- **Mech skills** (Hull, Agility, Systems, Engineering) gain allocation points with level. Pilot HP is 6 plus equipped gear bonuses; no level bonus.
- **HASE starts at 0** with 2 + level points (changed from the earlier "start at 1" for compliance; personal stats start at 2, with four shared extra points and a base maximum of 4). A one-line change in `sheetStats()` if the developer wants 1 back.
- **Mech stats:** structure, stress, HP, heat cap, armour, evasion, speed, e-defence, tech attack, repair cap, system points and size. Speed gains floor(Agility / 2); e-defence and tech attack each gain Systems; evasion uses the normal frame + Agility formula (no pending rework). Grit, save target and sensors remain excluded. Values are calculated, never stored.
  - **Permanent build effects (2026-10-29):** `mechEffects()` collects frame traits, passive core bonuses, equipped weapons/systems (including integrated items), pilot gear, owned core bonuses and purchased talent ranks. `bonuses.ts` handles safe arithmetic (known licence/HASE/size variables, no JavaScript evaluation), replacements and highest overrides. `mechStats()` and rule checks share these effects. Armour normally caps at 4, with `armor_max` modifiers; Fomorian Frame increments size up to 3. `equipment.ts` applies matching weapon range/damage bonuses, Hunter II Thrown, selected profiles, Limited bonuses (including floor(Engineering/2)) and drone/deployable modifiers. Damage dice are converted to the flat homebrew number (rounded up) once, after modifiers. `coreRules.ts` explicitly supplements permanent core check modifiers omitted from the pinned dataset's structured bonuses; `mechEffects()` adds a supplement entry only when the frame's (or core bonus's) own structured bonuses don't already carry it (newer data gives Exposed Reactor its bonus), so it never counts twice. Conditional abilities and active core powers are readable reminders, never treated as permanently active. The mech page's "other effects and conditions" list (2026-10-31) holds frame traits and their actions, the core passive and active power, core bonuses, talent ranks and bonuses not counted in the stats, in plain wording. An action named like its trait or core power (COMP/CON's data often has both) is listed once, under the parent, with the action's chip and text (trigger and effect); the same rule applies in the full-information dialog (`absorb()` in `info.ts`), where it also takes the action's numbers. Each reminder (`Reminder` in `mechData.ts`) carries its `kind` (frame, trait, core, core-power, core-bonus, talent, item, missing), its own `name`, where it's `from` ("Brawler I"), any `activation`, and `uncounted` for bonuses the stats leave out ("+10 hp, only when exposed.", then a dim "Not counted in the stats."). It leaves out frame lore, COMP/CON's repeated `synergies` hints, equipped items' rules (their cards show them) and pilot gear (only non-`pilot_*` bonuses count on a mech). Unknown expressions/effects stay manual and are not evaluated as code.
  - **Talent grants and mount choices:** integrated talent equipment appears automatically; exclusive grants upgrade to the highest owned rank, optional special equipment is selectable only while granted. Improved Armament, Integrated Weapon and Mount Retrofitting alter mounts; Auto-Stabilizing Hardpoints and Overpower Caliber target choices are per mech. Choices live in `sheet.mechs[id].core_mounts`; per-instance profile/prototype choices, a Variable weapon's chosen `damageType` and the weapon's description (`notes`) live in `weapon_options` keyed `mount:place` or `integrated:item-id` (a swap resets it, a removal drops it). System descriptions live in `system_notes` keyed by the system's index (a removal moves later ones down); pilot gear descriptions live on the owned item (`owned_gear[].notes`, see [pilot-inventory.md](pilot-inventory.md)). New fields are included in GM change review. Lost mounts/talent ranks, invalid targets and stale profiles are rule-checked without silently deleting saved gear. AI capacity includes The Lesson of Shaping. `mechResources()` displays AI/Limited capacity, structure repair cost, overcharge costs and permanent check accuracy separately from numeric stats.
  - **Scope explicitly confirmed:** permanent character-building effects and readable combat reminders only. No current HP, heat, overshield, status toggles, expended charges, turn tracking or active-core-power state.
- **Rules text** (2026-10-31): LANCER's rules text is small HTML. `src/rulesText.ts` parses it into an allowlist (paragraphs, bold, italic, underline, lists, line breaks; no attributes, other tags dropped) and `RulesText.vue` draws it with Vue, never `v-html`, turning top-level line breaks into spaced paragraphs (`paragraphs()`), because imported packs are untrusted. Styled by `.rules-text` in `style.css` (bold keywords in bold white). `plainText()` flattens it for one-line picker summaries. Don't strip formatting with regexes elsewhere.
- **No dice** (the developer, 2026-10-31): this homebrew involves no dice at all. **Damage** is a flat number: LANCER's dice expression converted by taking its mean rounded **up** (1d6 → 4; 2d6+1 → 8). It is the damage, not an average: never label or describe it as "average" (`damage.ts`; item cards show "kinetic 4"). Shared item cards/pickers and explicit damage phrases in rules text use this. Overcharge heat (1 → 1d3 → 1d6 → 1d6+4, or a frame's own list) is converted the same way, so the default reads 1 → 2 → 4 → 8 (`mechResources()`). Other dice left in game text (movement, rolls, Limited 1d6+2 and so on) stay as they are: the developer will give instructions for each or edit them in the content editor once it exists, so don't invent conversions. Variable/unsupported expressions remain visible; no guessed values.
- **LANCER rules compliance** (the developer's request, 2026-10-29): `docs/lancer-rules.md` records every character rule the site follows (licences, HASE points, mounts, Superheavy, Unique, AI, system points and so on), whether it's enforced, rule-checked, left to GMs or waiting on unbuilt features. The rules are in `src/rules.ts` (tested in `src/rules.test.ts`); `useCatalogue()` there gives the loaded game content in the shape the rule checks read, for the pilot sheet, mech page and change review. Keep that file current when rules change.
- **Core bonus equipment and mounts (2026-11-21):** `buildFrame()` takes the core bonus catalogue: a taken core bonus's `integrated` items join the mech's integrated items, its `special_equipment` is optional equipment (`talentGrants()`), and `replace_integrated: true` drops the frame's own integrated weapons (not systems). `add_mount` (val = any mount type, optional `max` = "only if fewer than N mounts") and `superheavy_mounting` (a Superheavy mount if under 3 mounts) both count mounts excluding integrated ones. `drone_hp` / `deployable_hp` already apply on item cards (equipment.ts). The editor's `EFFECT_BONUS_TYPES` lists the effect bonuses and their value kinds; `bonusCounted()` decides what the editor calls "not counted".
- **Homebrew effects (2026-11-21):** every kind's bonuses are collected where they apply: mech ids in `mechEffects()` (each source carries a stable `key`), pilot ids and the five personal stats in `pilotBonuses()` (gear, talent ranks, core bonuses, installed biomods) and `modPointLimit()`. Equipped weapons, systems and installed biomods grant equipment through `grantingSources()` and `talentGrants()`. Requirements: `unmetRequirements()` / `requirementReason()` in `src/rules.ts`. Biomods read `effect_bonuses`, `integrated`, `special_equipment`, `replace_integrated` and `requires` from the bionics table once those columns exist. Rules table: `docs/lancer-rules.md`.
